# 家庭账本前端重设计与实施方案

日期：2026-09-15。基线：`experiment/astra-simplified` / `9c713fe`。
本文是本次重设计的实施依据；完成情况另见 `FRONTEND_PROGRESS.md`。

## 1. 目标与已验收边界

这是两个人一起了解家庭财务的小网页。打开首页，先回答「家里现在有多少资产」「这个月花在哪里」「还有什么需要我处理」。中文简洁、温暖、克制，避免运营后台的密集表单和技术状态。

用户本次交接优先于旧交接：S1/S2 已验收；S3 余额截图实际识别 Wallet ¥14,424.51、选账户、保存财富余额已通过。真实信用卡 PDF 的上传和模型提取可用，但金额符号和最终审核导入体验未验收。S4 投资区间、投入后的收益变更、未登录/伪造 JWT、设备创建与即时撤销通过实际功能验收。最新版 S34 的真实 Shortcut、JWKS 换钥等仍待验收。不得据此宣称生产切换就绪。

本轮先落完整方案，再实现并验证；5 小时额度剩余 <=10% 时停止增加范围，整理测试结果、改动、启动方法、已知问题及下一步到磁盘。额度规则覆盖 PROJECT_CONTEXT 中旧的取消监控说明。不自动使用重置信用。

## 2. 实现审查与根因

| 现状 | 根因 | 处理 |
| --- | --- | --- |
| 账单每行约十余个控件，25 行分页仍极长 | `statement_page.py` 把底层编辑模型直接展开为产品界面；分类确认、关联、分期同时展示 | 48px 左右的交易行；只为选中行展开详情；疑点先行；整单一次提交 |
| 刷新后重新登录 | `login_session.py` 仅使用 Streamlit `session_state`，浏览器刷新建立新会话 | 浏览器持久登录，自动刷新令牌，后端继续验证身份与家庭成员资格 |
| 复核页像几套页面拼接 | `app.py` 顺次渲染支出、余额草稿、账单、投资全表单 | 一个待办收件箱，按需要的动作分组，进入具体条目处理 |
| 财富难以一眼理解 | 指标纵向堆叠、观察/覆盖/汇率原始字段直接展示 | 家庭总览、三个明确指标、账户状态、真正有用的历史/分类图 |
| 中英文术语和错误泄漏 | API 错误字符串直接 `st.error`；内外模型共享标签 | 稳定错误代码映射自然中文；版本、幂等键留在程序内部 |
| 操作一次需要多次重跑，布局难控制 | Streamlit 的脚本重跑与服务端组件状态不适合密集编辑和长期浏览器会话 | 新增独立浏览器应用，旧 Dashboard 暂留作验收期间的回退 |

### 复用

完整复用 FastAPI、PostgreSQL、Supabase Auth/JWKS、家庭权限、余额与支出分离、参考汇率、投资收益算法、重复检测、版本检查、原子导入、持久命令回执、上传按键恢复、类别/账户/设备接口。保持迁移文件和已验收 Shortcut 接口不变。Streamlit 的控制器/测试作为契约参考和回退验证，不直接移植其控件结构。

### 架构决策

新增 `ai-ledger-web`：React + TypeScript + Vite，语义 HTML/CSS，按页面拆分。理由是紧凑编辑、局部状态、键盘访问、响应式导航、浏览器会话都属于此次核心问题，继续修补 Streamlit 会保留根因。无需 SEO、服务端渲染或新的财务数据库，不引入完整 SSR 框架。

生产入口为小型 Node 服务：静态构建文件 + `/config` 公开配置 + 固定后端 `/api/v1/*` 转发。同源 REST 避免为此修改后端 CORS，也适配现有 Cloud Run 架构。后端地址仅在服务器配置；转发仅白名单请求头，不透传 Cookie，不缓存财务响应，不跟随上游重定向。禁止任意 URL 转发。前端绝不持有数据库、Gemini 或 Supabase 服务角色密钥。

Supabase 官方浏览器 SDK 管理 `persistSession` 和 `autoRefreshToken`；登录后调用后端验证访问。浏览器内会话只负责携带令牌，授权仍由后端完成。退出清理本地登录和财务草稿；身份切换卸载旧页面，异步旧响应不得恢复旧数据。仅缓存必要的重试命令且按身份隔离，PDF/密码不落浏览器持久存储。浏览器丢失/禁用存储需给出清晰提示，不虚称已保持登录。生产 CSP 限制脚本来源、不加载第三方统计脚本。

官方参考：[Supabase 初始化](https://supabase.com/docs/reference/javascript/initializing)、[读取会话及信任边界](https://supabase.com/docs/reference/javascript/auth-getsession)、[Vite 生产构建](https://vite.dev/guide/build)。采用其浏览器会话与构建机制，实际依赖锁定在 package-lock 中。

## 3. 信息架构与视觉体系

| 一级入口 | 首要问题 | 主要内容与动作 |
| --- | --- | --- |
| 我们的家 | 家庭财务最近怎么样？ | 净资产/资产/负债，本月支出、分类分布、需要处理、余额更新提醒，记一笔/导入账单 |
| 日常支出 | 钱花在哪里？ | 月份与筛选、净支出/退款、紧凑记录列表，新增/修改/作废，月度计划，账单入口 |
| 家庭财富 | 钱放在哪里？多久没更新？ | 账户卡片/列表、余额日期、净资产历史、正资产风险分布、余额更新、截图、投资收益与投入取出 |
| 待处理 | 现在具体要做什么？ | 待保存账单/截图/消费，已入账但缺账户或分类的记录，待确认计划、异常投资变化 |
| 设置 | 两个人怎样共同使用？ | 账户、分类、设备、提醒阈值和退出；历史/不常用生命周期动作渐进展开 |

暖白背景、深绿主色、杏色提示、柔和边框和留白；少量家的图形点缀，不以插画占用财务信息。金额等宽数字，中文系统字体，不依赖外部字体 CDN。桌面侧栏、移动端底栏。颜色不独立传达状态，均有文字/图标。控件有标签和键盘焦点；弹窗管理焦点和 Escape；等待、空、失败、成功都有明确状态。

文案：复核→待处理，观察→余额记录，estimated→暂按没有额外投入或取出估算，category_uncertain→分类待补充。禁止把 row_version、provider ID、request ID、原始 JSON 作为普通页面内容。

## 4. 首页与有用的图表

首页三个财富数字同排，首位净资产。缺余额/汇率时显示「已知净资产」并说明还缺哪些账户，未知不能显示为零。旧余额仍计入，标注最近更新日期。信用卡欠款/溢缴款分别展示。

分类横向条形图回答「钱主要花在哪里」，注明退款已抵扣；负净支出的退款类别显示符号与金额，不伪造正向占比。月份变化只在完整可比时间窗口及汇率覆盖下给出结论，月初零基数不制造百分比。历史净资产按后端实际余额事件绘制阶梯线，缺失段不连接，不能用平滑曲线暗示连续追踪。风险图仅对已知正资产；负债不进入分母。投资收益按币种展示，估算与已确认分别标注，不能把汇率或资金投入当收益。

## 5. 账单：最优先的完整操作链

1. 选账户 → 上传 PDF → 可选密码。20 MiB、50 页限制可见；密码仅用于本次请求。等待使用真实阶段的简单文字，不编造进度百分比。
2. 识别完成显示账户、账期、消费/退款/还款数量、消费与退款合计和待检查数。同币种精确十进制求和，不混加币种。还款与转账明确不计支出。
3. 默认紧凑表格：日期、商户、性质、分类、金额、处理状态。正常 1366×900 桌面首屏至少 10 行；表头/底部操作固定，滚动列表。100 行保持直接扫描；可切「只看待检查」和按商户搜索。键盘 Tab 可逐格编辑，详情按需展开。
4. 高置信正常消费零逐笔动作；分类不确定保留「待分类」允许整单保存，之后只作为补充信息出现。低置信金额/日期/性质、重复、账户归属、部分页缺失仍要求针对性处理。
5. 退款默认保留来源说明「账单退款 · 商户」满足未关联退款的既有语义；不要因符号改变交易性质。对于只有退款标签但分类不明的行，使用后端默认类别并标记待补充。
6. 重复提示提供「已记过」「是另一笔」「跳过」；关联已有记录和分期只在详情显示，目标从 API 获取并保留版本，不能输入内部 ID。确认一行只能改变该行，切换筛选/页码不能确认未看过的疑点。
7. 期末余额是独立可选项；明确金额、日期和账户。信用卡月账单金额不能当总欠款，无法确认范围默认不选。保留相同余额记录的复用，冲突由后端重新核查。
8. 一个「确认导入」按钮：先保存必要编辑，收到新版本且无阻塞警告后再确认整单。收到新增重复/并发变化时停在当前表格提示处理，不继续确认。完成显示新增/关联/跳过和余额结果。
9. 未知上传结果通过原键查询或取消；不能自动换键重复上传。保存超时保留相同命令和参数，刷新后可恢复；对于基于版本的草稿更改，先读回确认是否已经生效，再决定重试。不要错误宣称 exactly-once 网络传输。

### 金额符号修复

修复位于新 statement transport→draft 的边界，使用 Decimal，不修改所有财务写入的正数约束。模型明确返回金额绝对值和独立 kind；兼容实际输出为负数时，已明确的交易 kind 将有限数值归一为绝对值。保留原始模型提取在 statement_lines 中用于追溯。`unknown` 不依赖正负推断方向，仍进入待处理；零、非有限数值、货币精度不合法仍由现有验证拒绝。余额字段维持原有资产/负债符号语义。

回归包含两种银行相反 +/- 约定、借/贷栏、消费/退款/费用/还款/转账、零、NaN/Infinity、未知性质、原币金额、输入不被修改以及正确来源备注。新增真实数据库测试验证规范化后整单导入、退款净额、还款跳过、重复幂等。

## 6. 待处理：异常收件箱

先用短摘要表达发生了什么和需要哪一个动作：如「午餐 · ¥38，需要选个分类」「信用卡账单 · 42 笔，3 笔待检查」。已保存交易补资料只 PATCH 原记录，不再次记账。未保存草稿进入对应编辑器；不在收件箱内渲染整份账单。单个项目处理成功后移除，刷新总数。计数按后端真实 section counts，不能把所有缺失字段相加造成重复项目数。

投资变化采用「这段时间有额外转入或取出吗？」输入两个金额，可明确确认为零。显示起止余额日期和收益变化，继续遵守后端的相邻余额配对及版本校验。月度计划保留确认/跳过/暂停/恢复和完整金额转分期能力。

## 8. 验收矩阵

- 会话：登录→刷新→深链接→仍在原页面；临近过期刷新；多标签登出；第二位成员不能看到第一位成员内存/恢复命令；401 返回登录且保留同身份未确定操作。
- 账单：40–100 行，首屏 >=10；高置信整单一次确认；疑点筛选/跨屏修改/针对性确认；正常行不触发确认框；退款与还款语义正确；上传/保存超时恢复；重复提交不增加记录。
- 财富：真实零、未知、欠款、溢缴款、多币种与缺汇率、30/90 天旧余额、历史间断；手动与截图更新、纠错/作废；投资投入后收益变更。
- 支出：月份/分类/账户筛选，新增、编辑、退款、作废、月度计划；服务端分页不会假装已加载全部结果。
- 待处理：各类计数、单项动作、完成移除、空收件箱，不暴露财务内部字段。
- 设置：账户/分类修改、账户别名、设备凭据只在创建时展示、撤销失败提示、阈值修改与版本冲突。
- 包装：`npm ci`、类型检查、测试、生产构建、本地 Node 服务、Docker；配置仅公开 URL/发布密钥/时区；无演示数据流入正式 API。
- 真实托管验收：两位家庭用户、真实 PDF、浏览器刷新/重开、iPhone、最新 Shortcut 和 JWKS 换钥由专门步骤记录；本地 mock 通过不替代这些验收。

## 9. 取舍与风险

本次增加 Node 工具链和一个前端服务，换取可控交互与持久登录；保持后端财务代码改动小。浏览器持久会话使用 SDK 的标准本地存储，需配套 CSP、无 HTML 注入、无第三方脚本；未来若有更高威胁模型，可单独引入共享会话存储与 HttpOnly BFF，本轮不额外增加分布式会话系统。

前端最多呈现金额和统计派生视图，后端始终决定可否入账。宽松批量处理降低非关键分类的摩擦，不削弱金额/币种/日期/重复/账户/授权/原子性约束。计划中的所有验收应标注实测状态，未完成项明确留在进度文档。
