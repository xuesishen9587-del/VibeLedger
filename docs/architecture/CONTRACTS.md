# 业务约束与实现边界

本文件保留无法由 OpenAPI／SQL 字段定义独立解释的规则。依据当前实现；原“目标模型”中未实现的承诺已去除。入口见 [README](../../README.md)，配置见 [运维说明](../deployment/S6_PRODUCTION_CUTOVER.md)。

## 1. 业务事实

支出记录和账户余额观察相互独立。账户余额来自某时刻的外部报告，不由交易累加推算。账单可同时提供支出和期末余额，但二者互不推导；没有 account_state、结算腿、对账调整或完整现金流承诺。

金额使用 Decimal／NUMERIC／JSON 字符串。当前财务入口支持 CNY／SGD／USD／EUR（两位小数）和 JPY（整数）；原币超出小数位必须拒绝，不能先舍入再接受。换算金额使用 ROUND_HALF_UP；不接受零消费、负消费、NaN 或 Infinity。原币始终保留，账户币种与消费币种可以不同。业务日期必须有效且不晚于家庭当前日，捕获时间需要时区偏移且不能在未来。

## 2. 身份与存储隔离

- Supabase JWT 的签名、issuer、audience、expiry 验证后，以 sub 查内部用户及唯一有效家庭成员关系。无映射、禁用或多个有效家庭不能获得财务访问；客户端不能选择家庭。owner 和 member 共享家庭财务权限，账户 owner 仅表示归属。
- 设置页从浏览器专用 GET /household-members 读取当前家庭成员的内部 user_id、名称和状态，归属创建／修改复用 accounts.owner_user_id。未设置保留 null，不能从登录人、设备或历史记录自动推断；可显式清空。停用成员保留原归属展示但不提供新的界面指派；成员读取失败时不发送归属字段，防止误清空。归属变化不修改历史金融事实或共享权限。
- 设备 bearer 不透明且只返回一次，库中只存 SHA-256 hash。每次认证检查设备、用户、成员和家庭状态；撤销即时影响后续请求。JWT 失败不能退回设备令牌认证。
- 设备创建只允许浏览器；列出／撤销限定当前用户，并没有家庭 owner 管理其他成员设备的特权。创建不具持久命令回执：丢失响应先查设备列表，不能盲目重建。
- 查询带 household_id；复合外键防止跨家庭引用，历史外键 RESTRICT。财务表在显式私有 schema，search_path 不回落到 public；扩展命名空间单独限定。
- actor／user／device 来源由服务端认证决定。设备只能读取／修改自身 actor 的回执；同家庭浏览器可按 ID 处理家庭草稿，按键恢复仍限定自身 actor。家庭共享访问不等于设备间共享幂等键。
- 有效账户／分类名在各自家庭范围内不区分大小写唯一；别名可跨账户重叠，匹配歧义不能猜一个账户。停用引用保留历史，不能通过删账户／分类消除记录。
- 审计追加且有数据库不可修改触发器，和实际变更同事务。普通表是财务事实源，不通过审计事件重放重建。回执随家庭数据保留，无短 TTL 自动删除策略。

## 3. 回执、锁与恢复

`ingestion_requests` 的唯一键是家庭 + actor_scope + idempotency_key，键长 8–200；浏览器用户和不同设备的键空间不同。请求 hash 包含操作及规范化参数，媒体只保存摘要；截图／base64／原始模型响应不入库。

| 状态 | 财务含义 |
| --- | --- |
| processing | 已预留，尚不能判断最终是否保存 |
| needs_confirmation | 已保存可恢复草稿，未确认财务结果 |
| committed | 已保存全部结果，返回持久结果 |
| rejected / failed | 无该请求新增的财务记录，终态可恢复 |

- 相同键、相同原请求重放已有状态／结果，不重调 AI；改变操作或参数为 409。短命令的变更与终态回执同事务，没有独立 processing 阶段。
- 普通财务命令和 PDF 上传使用 Idempotency-Key header；截图键在 JSON，按键 cancel 在路径。草稿动作沿用原回执而非另建命令键；设备创建例外见上一节。已成功命令先返回持久结果，再考虑旧 expected_version，因此丢失响应后可用原参数重放。
- 识别先预留回执并提交，释放连接后调用外部服务；收尾重新认证。先锁回执（多个按 ID 排序）、再锁家庭、再按稳定顺序锁记录，财务变更／证据／审计／终态原子完成。外部请求不得占着这些锁。
- 网络中断不等于失败。按原 actor／原键查询；浏览器可按 ID 查看家庭草稿。404 不能排除迟到 POST，按键 cancel 会创建拒绝 tombstone；迟到请求不能再入账。committed 不能被 cancel 撤销。
- 进程中断可能留下 processing；没有自动接管、重试 worker 或持久截图。显式取消并核实终态后，才可有意新建请求。`failed` 终态不会因 retryable=true 自动重跑；该标识不是自动换键许可。
- 浏览器草稿确认／修改／拒绝检查 expected_version。兼容设备无 body 确认，仅在最后编辑者仍为该设备时可用；浏览器改过草稿则返回 DRAFT_CHANGED，防止旧设备误确认。
- 设备 revise 未提供 expected_version 时可修订浏览器编辑后的当前草稿并接管 last_editor_scope，之后无版本确认可通过。这是原契约允许的兼容策略；服务端仍检查修订期间并发变更，不是已经证明的授权漏洞。不能宣称全部设备动作都有相同的过期上下文保护，手机实际审阅限制见 Shortcut 文档。
- 结构化 patch 未传字段保持原值；显式 null 仅可清空可空字段。草稿可以保留尚待补正的事实，但无效必填事实不能确认；终态重放不会因旧草稿版本再产生一笔。
- React 的登录由 Supabase SDK 存 localStorage；未确定命令按用户存 sessionStorage。刷新可恢复，关闭标签页／显式退出可能失去本地恢复信息，但服务端事实仍在。不能承诺任意设备自动找回所有原请求参数。

## 4. 消费识别、分类与纠错

当前识别默认模型 `gemini-3.5-flash-lite`，提供受约束的结构化提取；字段置信阈值 0.85。Gemini 读取有效账户别名和分类名称／说明；图中文字和备注视为非可信输入，不能改变权限、创建账户、指定风险或执行命令。

- 自动保存要求消费性质、金额、币种、日期证据可靠。缺日期仅在明确 current_payment 证据下取捕获时刻的家庭本地日期；不能把上传日当历史支付日。
- 已明确失败、转账、还款或退款拒绝按普通消费捕获；性质不明确、待完成或证据冲突需要审核。退款用正常退款流程。
- 账户不明确则 null 并提示补充，不能猜默认账户；分类不明确使用有效 Other 并标记待分类。这些资料不足不等于关键金融字段不可靠，也不能因此丢掉明确消费。
- 消费截图匹配以账户名称／别名／卡片与持有人证据为先；Gemini 保留所有有证据的候选，服务端仅在歧义候选中存在唯一上传者名下账户时优先该账户。上传者来自已认证设备 user_id，归属来自 owner_user_id；不排除未归属账户，不用身份补造账户证据或提高置信度。同一人多个候选、无身份或不可靠证据仍保留未知账户提醒；明确其他成员账户优先于上传者归属。仅影响新截图识别，不重新匹配已存草稿、人工修订或历史交易。
- 分类是可编辑的数据，不是固定 Literal 或独立规则引擎；稳定 ID 保留历史，fallback 可改显示名称但必须保持有效。初始分类的易混规则：儿童相关优先 Child；给父母现金属 Gift & Socials、为父母购买具体商品属 Parents；成人软件／AI 订阅属 Education；贷款本金不属支出，可辨识房贷利息属 Home & Utilities。完整种子直接查 bootstrap，不重复列全部分类。
- 截图 JPEG／PNG 经严格 base64、类型、尺寸验证，当前上限 10 MiB／20 MP；外部识别超时与总截止时间有界，失败只写安全回执。
- 自然语言 revise 只针对已存草稿，通过允许字段 patch 和本地验证，仍保持 needs_confirmation，不自动入账；失败不能覆盖原草稿／版本。
- 初始 API 的 note 会参与识别，但当前初始草稿 remarks 为 null；自然语言 revise 不提供 remarks 字段。交易备注应通过结构化编辑保存，不能宣称识别备注会自动成为持久备注。
- 不同新键仍可能捕获同笔消费。当前候选匹配同家庭有效消费的业务日／原币金额／币种／规范化商户（大小写、空白归一），账户相同或任一未知；截图另检查相同图像摘要关联。候选必须审核，不静默删除；确认表示另记一笔，确认前新出现的候选须再次审阅。没有模糊商户／不同裁剪图片／跨设备新键的无条件 exactly-once 保证。
- 明确分期证据必须选择 record_full_purchase 或 use_schedule_period，不能默认当一笔完整消费；选择计划月份需验证对应期次，不能随意绑定未来月。

## 5. 支出、退款、月度计划

expense、refund、cash_income 均为正原币金额。净支出按收到退款的日期减退款；现金收入独立统计，不计算 net_cash_flow／储蓄率。账户可空，未选账户的资料提醒可以确认，但不能伪造已绑定账户。

已保存交易的 category_uncertain／account_review_acknowledged 是补资料状态，不撤销其报告贡献。明确选择有效分类（包括 Other）可消除分类不确定；确认未知账户仅消除待处理提醒，缺账户筛选仍应包含。清空账户会重新要求确认，除非同时显式确认未知。交易性质不能通过普通 PATCH 改写；历史停用引用可在无关字段修改时保留，新指派仍须有效。

当前 [Home](../../ai-ledger-web/src/pages/Home.tsx) 最近交易列表只为 refund 加正号，cash_income 也显示负号；这是代码可确认的展示差异，不改变后端存储或净支出算法。同文件也没有 Spending／Review 使用的计划补记门禁，见本节末尾。

关联退款必须指向同家庭、同币种的消费，活动退款合计不超过原消费。退款创建时复制原分类；后续原消费改分类不自动传播。有关联退款时不能随意作废原消费或将其减至退款以下。未关联退款需要明确来源说明与分类。API 支持关联退款，当前 React 手动退款表单主要提供未关联录入。

月度 recurring／installment 计划只记录支出，不发起支付：

- 指定月份与扣款日，月底不足天数取最后一天；不预建未来交易。有限期数 1–1200，只有 recurring 可无限。
- 创建／转换先预览并确认 acknowledged_due_through；日期变化拒绝旧预览。补记回溯到期月，编辑／暂停／恢复前先按旧条款补齐已到期部分。
- 暂停期间记为 skipped，恢复不回补暂停月。计划 + 月份唯一；作废交易也不允许自动生成该月第二笔。
- 任一期已生成后，start_month／day_of_month／currency／kind／merchant 固定；金额／分类／账户／期数修改只影响以后期次，已捕获的待确认期次保留原条款。期数不能缩至已生成期次之前；取消只跳过待确认期次，不作废已有交易。分期费用若已含在期金额，不能另补一笔费用。
- 与截图／账单等疑似同笔时进入确认，可关联既有记录、明确另记或跳过；没有静默覆盖。失效账户转为缺资料，失效分类转有效 fallback。
- 完整消费转分期必须同事务作废原消费并建立计划，期数总额一致、币种一致、无未解决关联退款。使用未确认消费草稿建立计划时消费草稿被消费为终态，不能之后再确认成整笔。
- Google OIDC 内部任务与浏览器补记调用相同幂等逻辑。Spending／Review 进入时先补记，失败提示并允许恢复；报表 GET 只读取。当前 Home 没有相同补记门禁，也未显示 schedules_current_through，任务失效时首页支出可能滞后。

## 6. 余额观察、范围与生命周期

账户为 cash／savings／investment／credit、单一币种、显式 balance_scope。配置新账户不代表余额为零。有财务引用后类型和币种不能改变。risk 由用户设置为 very_low／low／medium／high 或 null，credit 只能 null。

- 手动保存已经是确认；截图可靠且范围清晰的行可自动提交。一次最多 50 个不同账户，整批原子保存。
- 每行检查账户版本和 expected_latest_snapshot_id，避免覆盖在此期间新写的余额。过去观察不会替代较新的当前余额。
- 有效观察不可原地改金融事实；纠错为作废 + 新观察，记录 replaces_snapshot_id；作废带原因。未来时间、相同瞬间冲突拒绝；账单可显式关联完全相同的已有观察，见第 8 节。date_only 与当日本来无法排序的观察不能靠“最后写入”解决。
- 历史 date_only 按家庭当日末尾处理；当前无显式日期的清晰截图以捕获瞬间处理，不生成未来观察。
- 账户覆盖应扁平且不重叠，如券商总额已经含现金／持仓就不能再记子项。已知完整范围才校验总数，明示精确金额必须相等；明示四舍五入的容差仅为各显示单位半个单位之和。不能用旧固定金额阈值吞掉差异。
- 近似金额需用户审核；不完整范围只提示“总额不可比”，不能补造缺项。未知行必须处理或明确排除，不能静默丢弃。
- 草稿行有稳定 ID，修改必须保留并明确排除行，不能用省略行表达删除。AI／单张图的总数验证不能证明不同账户或跨次上传范围不重叠；用户仍须维护账户范围。投资余额保存也不等于确认外部资金流。
- 信用卡／借贷记全部欠款／本金为负，不能把本月应还、最低还款、信用额度当总债务；溢缴款为正，不混作负债。
- 关闭账户要求指定有效、同币种的零观察且无更晚有效观察；未使用账户才可取消。后续纠错必须保留关闭条件或明确 reopen，生命周期影响历史纳入。
- **当前日期边界差异：** 新账户未传 opened_on 时使用服务器 date.today()；关闭检查直接取观察时间的 date() 且允许早于 closed_on，余额纠错却要求家庭本地关闭日等于 closed_on。不得把这些入口描述为已经一致，特别要注意跨日／跨时区情况。

## 7. 财富、汇率与投资收益

财富在时刻 T 按账户生命周期纳入，并选 newest active as_of <= T。正余额为资产，负余额绝对值为负债；净财富 = 资产 − 负债。缺余额／可用汇率返回 known_* 小计、缺项与 null 完整总额；空家庭显示待初始化。超过 30／90 天是更新／陈旧提示，不影响余额写入或自动剔除金额。

风险分母为已知正资产；null 风险和信用溢缴款归未分类，债务不参与，分母为零时比例 null。历史财富为观察／汇率事件形成的阶梯序列，首次观察前有缺口；补录／纠错会重述历史，跨时点余额不是同时点核验资产负债表。当前元数据不生成历史风险分布。

参考汇率方向为“1 单位 from_currency 对应多少 to_currency”，缓存按有效日 insert-once。消费尝试获取业务日或此前不超过 7 天的报价，首次获得后冻结；修改金额／日期／币种重算，仅改分类不重算。缺汇率仍保存原币，不能按 1.0 或零填充。

支出缺汇率时完整报告币种总额为 null，保留已知换算小计和原币汇总；覆盖完整不是余额新鲜，也不证明家庭全部资产／购买已录入。退款可使分类或月份净支出为负，界面不能为画饼图而吞掉负值。

家庭报告币种是 operator 配置，现有消费端没有更改它的入口；不能任意改变已有冻结换算的币种含义。

`POST /reports/refresh-fx` 有界重试缺失转换并审计，也可补当前财富报价。当前财富 GET 只读缓存，不会自行请求汇率；React 财富页提供显式刷新，未实现旧文档中的自动每会话／每天刷新。当前财富可用超 7 天缓存但标为陈旧；历史只用截至 T 且不超过 7 天的报价，否则视为缺失。

投资只用同账户／同币种的相邻有效观察：

```text
gain = closing − opening − contributions + withdrawals
```

- 投入／取出须覆盖整个区间；未确认时都按零估算，并非证明不存在资金流。显式确认零可标 user_confirmed；该词不是经银行审计确认。
- 区间为 (opening.as_of, closing.as_of]；取出含支付到账户范围之外的分红／分配。范围内部买卖、再投资、已体现在余额内的费用不另造外部流量或支出。本功能不推算持仓、IRR 或收益率；用户输入外部流量。
- 只有一个观察时收益不可得；异常估算依据家庭阈值和期初绝对余额，零期初非零变化需复核。阈值提醒不阻止财富更新。
- 纠错或插入中间观察使旧区间输入失效，不能按比例复制或在后来作废中间观察后偷偷恢复旧断言；重新确认需版本检查，历史仍保留。
- 作废资金流确认后区间回到估算；有效相邻配对可按当前输入版本重新确认。配对失效由变更审计顺序判定，不能只看观察时间猜断言是否仍有效。
- 请求区间仅聚合完全包含的观察区间，跨边界不按天分摊。当前汇总按原币区分估算与确认，尚无统一报告币种收益总额；收益不生成 cash_income，账单现金移动也不自动确认投资资金流。

## 8. PDF 账单与重复证据

选定有效且允许导入的账户；PDF 当前最多 20 MiB／50 页／1000 行，解析时间有界。加密文件密码只在内存，解密中间文件 finally 删除，不保存原 PDF。任何账单识别都先预览，不直接批量入账。

- 账户匹配、完整解析、金额／币种／性质／业务日期、疑似重复等必须处理；posting date 不能代替缺失交易日。明确 expense／refund 可将外部负号规范化为正金额，unknown 不靠符号猜方向。
- 页覆盖／行数不足时允许显式 acknowledge_partial 后导入已解析部分，不能宣称整份账单完整。确认时重新检查账户有效且启用导入；关闭开关不删除既有账单／历史记录。
- 费用是支出，退款按退款处理；转账、还款、收入、opening balance、投资买卖不作为此消费导入路径的支出。未关联退款保留明确来源说明。
- 同账户文档 SHA 预留防重复上传；新键不能绕过已处理／待处理的同文件，failed／rejected 的有意重试例外。每行稳定 ID 保留同金额、同商户多笔购买的数量。
- 普通 Gemini provider_reference 不等于可靠交易标识。只有经服务器审查的 provider namespace／adapter 才可强关联，当前通用提取没有这种可信命名空间；不同证据行不能仅凭重复 reference 合并。
- 业务日／金额／币种／商户与同账户或未知账户记录匹配时提示候选，必须选择“已记过／另一笔／跳过”。没有无条件跨来源 exactly-once 保证。
- 关联已保存记录只新增证据关系，不覆盖其金额或日期。金融纠错必须走正常有版本的修改，已作废来源不能静默复活。
- 可独立选择完整范围的期末余额，日期和版本另验；本月信用账单不可当全额欠款。旧期末余额不覆盖较新观察，不进行消费与余额差额对账。
- 同账户、同币种、同瞬间、同金额的已有有效余额可通过 reuse_snapshot_id 显式复用，仍检查账户版本和最新观察。不同金额须纠错或排除，不能自动覆盖。原始提取证据保留，草稿修正不覆盖证据；全部行跳过可产生零新增的 committed 结果。
- 确认再次核查版本、重复及选择。交易、余额、每行结果、关联、审计、回执全部同事务；失败全不保存。重放返回持久计数／ID，不重新解析 PDF。

## 9. 错误与证据

错误使用安全 code／request_id／retryable 等字段；不回传模型正文、密码或请求验证中的媒体。版本／请求状态／重复冲突通常为 409，输入非法为 422，授权为 401／403，跨家庭资源为 404；具体以路由为准。识别依赖失败使用通用 CAPTURE_DEPENDENCY_UNAVAILABLE。

Gemini 诊断只保留操作、回执／诊断 UUID、失败类别／阶段、异常类与上游数字状态码，排除异常正文／traceback／headers／prompts。普通读取或幂等重试不制造额外财务审计。缺汇率和收益不可得属于覆盖信息，不能使明确原币消费失败。

自动化测试证明其覆盖范围内的行为；真实 iPhone、外部模型兼容性、线上权限／镜像／任务需要独立证据。历史验收和产品范围决策见运维说明，不将旧检查点列为当前未完成阶段。
